# Outcome

图片详情弹窗在桌面端按图片比例动态伸缩，图片高度贴满左侧视窗且完整显示，消除上下大黑边；右侧详情面板和底部操作区保持稳定可用。

# Scope

- 重构 `ImageDetailModal` 的桌面容器尺寸、媒体区、图片约束和右侧面板布局。
- 覆盖 1:1、3:2、16:9 及其他横竖图片比例。
- 保留现有图片详情内容、按钮行为、权限判断、关闭交互和移动端全屏纵向适配。

# Non-goals

- 不修改图片生成接口、图片加载流程或历史记录数据结构。
- 不修改操作按钮文案、权限逻辑和弹窗交互协议。
- 不改变其他弹窗或图片网格布局。

# Acceptance examples

- A1：桌面弹窗根容器使用 `w-fit max-w-[92vw] h-[80vh] max-h-[720px]`，宽度不再固定为视口百分比。
- A2：左侧媒体区使用 `h-full w-auto flex items-center justify-center bg-black/40 min-w-0`，图片使用 `h-full w-auto max-h-full max-w-[calc(92vw-360px)] object-contain`。
- A3：右侧面板使用 `w-[340px] flex-shrink-0 h-full`，不会因图片比例收缩或被截断。
- A4：1:1、3:2、16:9 图片在桌面弹窗中高度贴满左侧视窗、完整显示，图片上下不出现由布局造成的大块空黑。
- A5：提示词和参数区域可独立纵向滚动，底部操作按钮保持完整可见；移动端继续使用全屏纵向布局。

# Constraints and invariants

- 弹窗右侧面板宽度固定为 340px，媒体区承担剩余宽度。
- 图片使用 `object-contain`，不得裁切图片内容。
- 外层和内部 flex 子项设置 `min-width: 0`、`min-height: 0`，避免长文本或极端比例撑破布局。
- 现有测试、类型检查、lint 和生产构建必须继续通过。

# Decisions

- 桌面端采用固定高度、动态宽度：高度为 80vh 且不超过 720px，宽度由媒体内容和 340px 面板共同决定。
- 图片以左侧可用高度为主约束，宽度按原始比例自适应；媒体区不再使用按比例计算弹窗宽高的固定宽度策略。
- 移动端保留全屏纵向适配，以避免小视口下 340px 面板与图片区域互相挤压。

- 运行前端完整测试、类型检查、格式检查、lint 和生产构建。
